## Goal

Make motion detection work in rooms with different amounts of background RF noise,
without the user hand-tuning a number.

## Why this step mattered

v0.1 used a fixed threshold. A fixed threshold is wrong in both directions: it
false-triggers all day in a noisy environment and misses subtle disturbances in a quiet
one. Deriving it from a measurement of the link itself is the first time this project
turned an arbitrary constant into something grounded in data.

## What changed

* Calibration was extended to measure not just the average but how much the quiet link
  wobbles on its own — the RF noise floor, as a standard deviation.
* The fast threshold became `baseline mean + max(fixed margin, K × baseline std-dev)`.
  The fixed margin exists so the threshold cannot collapse to zero on a very still link.
* A slow metric was added: how far the average RSSI of the last ~5 s has drifted from the
  calibrated level, reported as **SIGNAL SHIFT** — deliberately worded as "the radio path
  changed", not "a person is there".
* An RF activity visualisation drawn as symmetric rings with no blips and no bearings,
  specifically so it cannot be mistaken for radar.

## Setup / architecture

```text
2.4 GHz AP (phone hotspot) → Wi-Fi link → ESP32-S3 → USB CDC → Chrome Web Serial → dashboard
```

One RSSI sample every 50 ms. Exact room, distances and session conditions: **not
recoverable from current repository evidence.**

## Evidence produced

Measured on a real quiet link:

| Quantity | Value |
| --- | --- |
| Fast score (mean absolute adjacent-sample RSSI delta over 20 samples), quiet link | ≈ 0.01–0.02 |
| Contribution of a single 1 dB step over that window | 1/19 = 0.053 |
| Resulting fast thresholds, quiet link, Low / Medium / High sensitivity | ≈ 0.52 / 0.29 / 0.15 |
| Resulting fast thresholds, noisy environment | ≈ 3.8–4.9 |

No dataset was recorded. These numbers survive only because they were written into the
`mino` README at the time.

## Results

The adaptive threshold behaved as intended across quiet and noisy environments: the same
slider position produces very different absolute thresholds, because the noise floor
differs by two orders of magnitude.

## Problems / failures

The two-step Web Serial debugging from v0.1 is the more instructive failure and is worth
keeping. `a1673f0` added DTR assertion and claimed it as the root cause of a dashboard
that connected but streamed nothing — and the physical retest still failed. DTR is a
*necessary* condition on ESP32-S3 native USB CDC, but the actual wedge was unbounded
`reader.cancel()` / `port.close()` awaits that never settle when the device is physically
gone, fixed in `242110e` by racing every cleanup await against a timeout and reporting
`Cleanup completed: YES/NO`.

**The lesson that generalises: a plausible mechanism is not a confirmed diagnosis.** Do
not close out a hardware symptom as fixed until a physical retest confirms it.

## What we learned

* A threshold must come from the measured noise floor, not from a guess.
* Because RSSI is quantised to whole dBm, the natural unit for reasoning about thresholds
  is "one-dB changes per second", not an abstract number.
* A single scalar per packet has an information ceiling: it can say *something changed*
  and roughly *how much*, and it can never say *what kind* of change it was.

## Limitations

* RSSI gives no distance, position or direction. The README states this explicitly and a
  test enforces the wording.
* The planned physical experiment (0.5/1/2/3 m × direct path / near path / off-axis, plus
  a quiet control and an AP-movement test) was **never run**.
* **No raw data was retained**, so none of it can be re-analysed with a better algorithm.
  That gap is what directly motivated record/replay on the CSI branch — see
  [DEC-006](../DECISIONS.md#dec-006--build-recordreplay-before-any-detection-algorithm).
* An iPhone hotspot's power management and channel behaviour were part of the
  measurement and were not controlled.

## Decision

Move to CSI rather than run RSSI v0.3. Recorded as the branch point to `mino-csi`. The
RSSI geometry experiment is parked, not cancelled — see [ROADMAP.md](../ROADMAP.md).

## Fontys relevance

**Iteration 1 (Understand & compare).** A concrete, self-produced illustration of an
engineering trade-off: what a single-scalar RF measurement can and cannot support, with
measured numbers behind it rather than a citation. It also produced a reusable insight
about measurement quality — that the threshold question is really a noise-floor question.

Assumption that changed: that a sensible fixed threshold exists. It does not; the quiet
and noisy environments differ by roughly 100×.

Next research question it raised: what does the per-frequency structure that RSSI
averages away actually contain?
